# SM530 Support Notes

This branch supports the Nelsonic SM530 Game Watch titles represented in MAME 0.289:

- `nsmb3` - Super Mario Bros. 3
- `nsmw` - Super Mario World
- `nstarfox` - Star Fox

The implementation follows MAME's SM530 device model rather than introducing a separate package format. The ROM generator assigns SM530 packages CPU ID `3`, pads the 2K program ROM to the existing fixed `0x1000` program area, and appends the 256-byte melody ROM at `0x1000`, the same place used by the SM511/SM512 melody path.

## Generator Changes

- The manifest and converter understand `sm530` as a CPU type.
- SM530 packages are treated as melody-capable and require a `maincpu:melody` ROM.
- The MAME extractor can parse `CONS(...)` metadata as well as `SYST(...)` metadata.
- The MAME input parser can split an 8-bit `IN.n` port into two four-bit package rows. Nelsonic's low K nibble is stored in `S0`; its high KE nibble is stored in `S1`.

## RTL Changes

- CPU ID `3` selects SM530 decode, reset vector `0x3c0`, wake vector `0x000`, and the SM530 three-clock instruction cadence.
- SM530 opcodes were added for `KETA`, `ATS`, `ATF`, `SDS`, `RDS`, `TG`, `SABL`, `INIS`, `PRE`, `TR`, `TRS`, `TL`, and the SM530 variants of `ADX`, `LB`, and `INCB`.
- RAM address masking now supports SM530 `SABM` and `SABL`, plus the LCD RAM mirrors at `0x40/0x60` and `0x50/0x70`.
- SM530 LCD RAM is exposed through the existing SM500-style segment normalizer: x is the output group, y is segment bit 0-3, and z selects H1/H2.
- The live SM530 LCD output is latched from the canonical LCD RAM ranges `0x40-0x4b` and `0x50-0x5b`; writes through the mirror ranges still land in those canonical addresses before video sees them.
- The divider now supplies SM530 gamma flags for 10s, 1s, 0.5s, and 0.1s, plus the `DTA` 1/100s counter.
- Halt wake now treats any pending SM530 gamma flag as a wake source, matching MAME's `m_gamma` behavior.
- The existing SM511/SM512 melody path is reused with SM530's `0xff` melody step mask.

## Super Mario Bros. 3 Startup and Audio

Nelsonic Super Mario Bros. 3 has no separate Start input or hidden controller combo. Its Mode input is active-high Button 1, which is the Xbox-style B position in the current MiSTer mapping; Set is Button 2, the Xbox-style A position.

The authentic program spends approximately five seconds in its all-segment power-on test and ignores Mode during that interval. To start reliably:

1. Load `nsmb3` and wait at least five seconds for the test display to settle.
2. Tap Button 1/B for Mode.
3. Press D-pad Down, corresponding to the original bottom direction button, to enter play.

On the original watch, a normal start can be silent because the firmware boots with its melody/alarm-enable state clear. Sound is not selected by a hidden gameplay button combination. To enable it through the authentic watch UI, start from the clock display, press Mode to cycle through game and alarm, hold Set for roughly two seconds until the alarm display blinks, release Set, then use Mode to leave alarm setting and cycle back to game before pressing Down. In the reference test, three separated Mode presses returned from the blinking alarm-setting display to game.

This behavior was verified with the exact program and melody dumps in both MAME's SM530 model and the RTL. The alarm-setting path writes bit 3 of firmware RAM `0x37`; the game intro later tests that bit before executing `SME`. With the bit clear, the program deliberately branches around `SME` and stays silent. With it set through the authentic UI, the exact ROM executes `SME` and produces nonzero melody output.

The current package deliberately opts into a user-facing compatibility default through feature bit `0x20`. For this package only, SM530 CPU reads of RAM `0x37` see bit 3 asserted; stored RAM and both original ROMs remain unchanged. The normal Mode/Down start therefore reaches the firmware's own `SME` instruction automatically. The MiSTer `Audio` menu defaults to On and can mute the final output without perturbing the running melody state. An exact-ROM RTL regression reaches `SME` and observes 15,402 R-output transitions after the normal start sequence.

USB-2 independently confirmed visible 360x240 gameplay after waiting six seconds, pressing Button 1/B, then Down. The alarm-setting sound-enable sequence completed on hardware, but nobody listened and no audio was captured during that run, so only the digital exact-ROM audio proof is claimed.

## Star Fox HA1152/HMC Sound Effects

Nelsonic Star Fox combines the normal SM530 melody/R output with a separate Hitachi HA1152 custom sound-effect generator, called `hmc` in MAME. Its effect content is not hidden inside the SM530: MAME has the 128-byte `ha1152_001a` dump (SHA-1 `5dfb15eee3c57bbca80f485f68442e5f7c6bc5e4`). The manifest extractor records that `sfx` auxiliary ROM, and the generator verifies its type, region, size, and SHA-1 before copying the exact bytes into the package at `0x336400`.

`rtl/hmc_ha1152.sv` implements the behavior established by the public Star Fox logic captures and the dumped ROM:

- falling S2, S3, and S4 edges start ROM programs at `0x00`, `0x3C`, and `0x75`;
- their command dwell times are 3840, 2880, and 480 HA1152 oscillator ticks;
- simultaneous triggers use S4, then S2, then S3 priority, while any later falling edge preempts the current program;
- the output asserts immediately for a 256-tick startup interval;
- ROM bit 7 selects tone or noise and bits 6:0 select a terminal state in the maximal `x^7+x+1` pitch divider;
- tone toggles at a terminal match; noise advances an `x^9+x^5+1` sequence;
- pitch-divider state is continuous across ROM command and held-trigger repeat boundaries;
- a zero ROM byte terminates the pass, a trigger held low repeats it, and a released trigger lets the current pass finish;
- Quartus 17 maps the requested core clock to 98.3203125 MHz, and the RTL derives its deterministic nominal 312.5 kHz timebase with the exact `8/2517` rational enable from that mapped clock, without a fabric-generated clock.

The physical HA1152 has no reset pin and uses an analog RC oscillator whose rate can drift. The RTL's exact 312.5 kHz value is the deterministic nominal that aligns the available captures, not a claim that every original part runs at that exact frequency. Its oscillator continues and its noise state is retained through normal core resets; reset handling follows the live S outputs so SM530 startup does not create a false falling-edge chirp. The effect ROM is accepted only after all 128 addresses have been loaded.

`tools/hmc_reference.py` is the independent trace/ROM reference. Against the three public authentic captures it reports zero structural and edge mismatches, with worst edge placement within 0.321 oscillator tick. It also contains negative self-tests that reject deliberately incorrect trigger, divider, and command-boundary models. Focused RTL replay covers all three authentic trigger paths and their move, bomb, and kill effects.

The absolute power-up phase/seed of the free-running noise generator is not distinguishable from the available captures, so the core uses a documented deterministic nonzero seed. That phase choice does not alter the measured period, program structure, or trigger behavior. Final audible comparison still requires speakers or an audio capture; digital state and waveform checks cannot establish the connected analog listening level.

## Known Limits

- MAME marks SM530 BP3/BP4 LCD counter coupling as TODO. This core currently follows the implemented MAME display-enable behavior and does not model those unimplemented BP effects.
- The optional development debug overlay uses SM530-specific rows for `K/KE` input and last RAM write address/data. Core debug rows 4-8 expose SM530 LCD output groups 4-8 so hardware snapshots can distinguish CPU execution failures from LCD normalization failures. Release builds omit this overlay unless `CORE_ENABLE_DEBUG_OVERLAY` is explicitly enabled.
